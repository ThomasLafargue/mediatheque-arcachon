## 1. CE QUI FONCTIONNE BIEN

### Le chat (13 outils, tous opérationnels)
Chaque outil déclaré au modèle est effectivement implémenté et branché —
vérifié un par un :
`executer_requete_sql`, `generer_export_excel`, `generer_rapport_import`,
`lancer_analyse_acquisition`, `ajouter/supprimer/statuer_suggestion_acquisition`,
`ajouter/supprimer_suggestion_desherbage`, `enregistrer/supprimer_desherbage_effectue`,
`ajouter/supprimer_suggestion_mise_en_avant`, plus la recherche web.
Aucun outil fantôme, aucun outil orphelin.

### Sécurité — conforme
- **Le chat ne peut pas écrire dans le catalogue** : double garde-fou sur
  `executer_requete_sql` (obligation de commencer par `SELECT` + liste noire
  `INSERT/UPDATE/DELETE/DROP/ALTER/CREATE/REPLACE/ATTACH/PRAGMA/VACUUM`),
  appliqué aussi à l'export Excel.
- **Jetons séparés** : lecture pour le chat, écriture (`TURSO_AUTH_TOKEN_ECRITURE`)
  réservée aux seules opérations légitimes (suggestions, désherbage, import).
- **Aucun secret versionné** : `.env` ignoré, aucun `secrets.toml` dans git.

### Moteur de recherche — ordre cohérent avec les mesures
Les sources sont classées par fiabilité réelle (mesurée le 24-25 juillet) :
1. **Place des Libraires** (données Dilicom, série + tome fiables)
2. **Cultura** (série + tome via le `<title>`)
3. **Open Library**, 4. **BnF SRU**
puis les muettes (Decitre, Mollat, Manga News, Booknode) et les bloquées
(Amazon, Fnac, BDfugue, LesLibraires) en fin de liste, où elles ne coûtent
qu'un échec rapide.

### Veille — 4 sources orchestrées
`veille_hebdomadaire.sh` lance bien les 4 scripts, chacun tolérant aux pannes
des autres. Lundi 8h via launchd.

## 2. POINTS À CORRIGER

### ⚠️ A. `com.maat.backfillserietome.plist` — XML invalide
Le fichier contient `--` à l'intérieur d'un commentaire XML (ligne 25), ce que
la norme XML interdit. macOS l'a accepté, mais tout outil strict le rejette.

**Contexte aggravant** : ce service est **terminé et arrêté** (le backfill
série/tome est fini). Ce plist et son script `lancement_backfill_serie_tome.sh`
sont donc devenus obsolètes.

**Recommandation** : archiver les deux plutôt que corriger.

### ⚠️ B. ~240 lignes de code mort dans `app_conversationnel.py`
Dix fonctions définies mais **jamais appelées** :
`get_kpis`, `get_frequentation_mensuelle`, `get_rotation_genres`,
`get_top_titres`, `get_roi_acquisitions`, `get_suggestions_acquisition_liste`,
`get_alertes`, `exporter_suggestions_orb`, `traiter_fichier_depose`,
`chercher_note_babelio`.

Ce sont vraisemblablement les vestiges d'un tableau de bord abandonné et d'un
export ORB jamais finalisé. Elles n'ont aucun effet (jamais exécutées) mais
alourdissent un fichier déjà volumineux (2 622 lignes).

**Recommandation** : supprimer, ou déplacer dans un fichier d'archive.

### ⚠️ C. Sources retirées encore citées

son `robots.txt`, Google Books mesuré inutile le 25/07 : 1 livre trouvé sur 8,
0 information de série, 5 erreurs 503).

**Risque réel** : faible, mais le prompt système peut induire le modèle à
mentionner des sources qui n'existent plus.

**Recommandation** : nettoyer ces mentions.

## 3. POINTS D'ATTENTION (sans action requise)

### Prompt système volumineux
**37 191 caractères (~9 300 tokens)** envoyés à chaque appel. C'est beaucoup,
mais le **prompt caching** (activé le 23/07) en neutralise l'essentiel du coût
et de la latence. À surveiller s'il continue de grossir.

### Fichier principal volumineux
`app_conversationnel.py` fait 2 622 lignes et mélange trois responsabilités :
définition des outils, interface Streamlit, logique de conversation. Ça reste
maintenable aujourd'hui, mais un découpage serait souhaitable s'il dépasse
~3 000 lignes.

### Rapprochement veille ↔ fonds : deux niveaux de fiabilité
- **Place des Libraires** : rapprochement par **ISBN** → exact, aucun risque.
- **BnF, Ricochet, prix littéraires** : rapprochement par **titre normalisé**
  → approximatif (ces sources ne fournissent pas d'ISBN). Ce sont des pistes
  à vérifier, jamais des certitudes. C'est documenté dans chaque script.

### Classement des suggestions : deux qualités
Les suggestions Place des Libraires arrivent classées (catégorie/public/genre)
depuis le moteur. Les anciennes ont été classées rétroactivement par mots-clés
(126 sur 237), méthode approximative — suffisante pour filtrer, pas pour du
catalogage.
